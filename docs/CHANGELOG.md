# What changed

























## Error reports (Sentry) and page counts (PostHog) on the public website

By the owner's direction, the web app now reports anonymous errors to Sentry and a count of which section is opened to PostHog, both tagged `app=cathology` (`src/lib/telemetry.ts`). Scope and limits: production builds on a real host only; never in a store app, Kid mode or development; off if the browser sends Do Not Track or Global Privacy Control; on unless the person turns it off (new Settings switch, "Share anonymous error reports and page counts"); loaded lazily so the first download is unchanged. No cookies or browser storage, session recording, click capture, breadcrumbs, tracing, feature flags or person profiles. Only the first part of the route is ever sent (`#/read`, never the book, chapter, search words or notes): checked in a browser, a visit to `#/read/dra/JHN/3?q=secret` sent only `#/read`. PostHog's other address properties (session entry address, referrers) are removed. The PostHog region is set by `VITE_POSTHOG_HOST` (default US cloud). The privacy policy, the Terms, the Settings privacy text and `docs/LAUNCH.md` now say so. The entry-chunk budget was raised from 380 to 382 KB on purpose (15 feast names in the calendar and the small loader; the Sentry and PostHog code is in separate chunks).

## Daily quotes: six "verified" lines made word for word, uncertain attributions marked, flags reclassified

A review of the 223 `needsReview` flags the social exporter raises over a year (209 "saint line unverified", 14 "attribution note"; none fall between 29 November and 24 December) found three things.
- Six lines were marked verified against a library work, but the wording on the Today screen was a modern paraphrase of it, so the "checked word for word" claim was not true: 1 Jan (Augustine), 30 Jan (Teresa), 5 Mar (de Sales), 13 Mar and 30 Mar (Thérèse), 27 Dec (1 John 4:16 as quoted by Cassian). Each now reads exactly as the library text does (so for example 1 Jan is "Thou madest us for Thyself, and our heart is restless, until it repose in Thee."). A test (`tests/dailyQuotes.test.ts`) now checks every verified line against the section it cites.
- Forty unverified lines appear under more than one saint (for example "To serve God is to reign" under three, "The soul is more where it loves than where it lives" under three). They are now marked as uncertain attributions, so the Today screen says so instead of presenting one saint as certain. The source is `data/curated/daily-verify.json` (new `duplicate` note), and `public/data/daily/index.json` was regenerated from it.
- The 209 unverified lines are not an error and cannot be verified without a source, so they stay unverified; the exporter no longer lists them as flags (each one's card simply leaves the line off, and the export prints a one-line count). The 14 attribution notes are already part of each line's `who`. Real flags remain for a reading that cannot be placed or a missing line: there are none.
- `scripts/verify/daily-quotes.ts` re-checks the library for lines that could now be verified (four turn up quoted inside Liguori and Leo XIII: leads for a person, not proof).

## A deleted StudyBible account no longer comes back; a link that was already used now says so

The marker was never removed, so every later start that found no account quietly made one again, including after the person had deliberately deleted it. The marker is now removed right after the account is first created (at sign-up, on first sign-in after confirming, or when the person chooses to create it) and again when the account is deleted. Tests cover creating once, not recreating after a deletion, and clearing the marker on each path.
- **A used or unusable link** (it comes back with `?code=` but nothing is signed in and no reset is waiting) now lands on the Account page with "That link was already used, or has expired. Request a new one." instead of a silent home page.
- Not changed, and unknown: whether Supabase itself accepts a reset link a second time from another browser. In the retest the second click arrived in a browser that was already signed in, so the sign-in could have come from that session and not the link.

## Sync through the reader's own Google Drive (built, off)
- Notes, highlights, bookmarks, journal, plans, progress, folders and some settings can now sync between a person's devices through the hidden app folder of their own Google Drive, with no server, database or account of ours. It works from the plain GitHub Pages copy.
- It reuses the existing sync engine unchanged (conflicts, deletions, the "unsent" bookkeeping): Drive stands in for the server through the same call. Each push is a small immutable file, so devices never write the same file; a device remembers which files it has read; a snapshot folds a long log into one file; unreadable or newer-format files are skipped and never deleted.
- Off and invisible: a normal build shows nothing and sends nothing (switch: `VITE_DRIVE_SYNC=1`, or `VITE_DRIVE_SYNC_PREVIEW=1` with `?drivesync=on`). Needs the Google client id the Drive backup already uses. Exclusive with an account on a server.
- Honest limits: Google's key lasts an hour, so sync stops with "sign in again" until one tap on Sync now; changes arrive when the other device next syncs, not live. Tested against a pretend Drive folder with the real engine (19 new tests); not yet run against the real Google Drive. See `docs/DRIVE_SYNC.md`.

## Sign in with Google, Microsoft or Apple (built, off)
- The server can now sign people in through OpenID Connect providers: Google, Microsoft and Apple are built in. It uses the authorization-code flow with PKCE, a one-time state and a nonce, and checks each ID token itself (RS256 or ES256 signature against the provider's keys, issuer, audience, expiry, nonce) with no new library. Login attempts are kept for ten minutes in the existing SQLite file, so there is still no external database.
- Off by default and invisible: the routes only exist with `OAUTH=on` and a provider's credentials, the Account page shows buttons only when the server lists a provider, and that page itself is behind the existing accounts switch. Start-up refuses a half-set provider or a `PUBLIC_URL` that is not https.
- Safety choices: a provider account is never joined to an existing account by email (it is added from the signed-in account page); an email the provider does not vouch for becomes a placeholder address; an account with a second step is not signed in by the provider alone; the last way to sign in cannot be removed; an account made with a provider can set a password when signed in.
- Tested against a pretend provider that signs real tokens (29 new tests, including forged, expired and replayed tokens). Not yet run against the real Google, Microsoft or Apple.
- `docs/SIGN_IN_PROVIDERS.md` lists exactly what to provide for each provider and answers the question about databases.

- Lessons now open as a short step-by-step journey with one part on screen at a time and a progress bar: adults and high school (Begin, Scripture, Teaching, Witness, Discuss, Practice, Pray and check), middle school the same with games in the practice step, elementary (Listen, Learn, Play, Talk, Do, Pray, Check) and primary (Story, Wonder, Play, Do, Pray, Check). "Whole lesson" brings back the long page.
- Catechism paragraphs show their first two sentences with "Read all"; Scripture passages show the first eight verses with "Keep reading". Facilitator hooks ("Ask the group…") no longer appear for participants.
- Word definitions: older readers see at most three words worth knowing, folded away, and the slides use one combined slide instead of one per word; common words are no longer defined.
- The lesson games now sit in a chip grid that cannot overlap on phones.
- Games on Learn is a direct link to the games room, with no expanding menu. The games room has a new playful look: letter-block title, a robot with tips, marquee-light hero, sticker cards, doodles, and a Surprise me dice.
- Verse notes open with "Yours", then "Start here" (the 3 to 5 most relevant items), then grouped lists; "More in this app" links lessons, chains, stories and readings to the verses they discuss. Apologetics tracks (39 topics, 4 levels each) point to verified free resources and the app's own sourced content.

- **Lesson lists** show minutes with a group and on your own, a teaching-depth badge and unit totals; grade pages and Learn offer "Continue your lesson" at the saved step.
